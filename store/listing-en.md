## Long description

Limit: npm README has no length limit; n8n has no long-description field. Use this text as the "About" part of the npm README, on /en/integrations/n8n/ and in the Creator Portal request. This text: about 843 words.

### What it is
My Store Locator is a store finder for websites. You manage stores, branches, dealers or partners in one web app and publish them as a searchable map with a list. Visitors search by city or postcode, filter, see opening hours and plan a route. The service is run by Internet am Dornbusch in Frankfurt am Main and hosted in Germany.

These community nodes connect n8n to the My Store Locator Customer API. Your workflows can keep locations in sync with a spreadsheet, CRM or ERP and pass map enquiries to the right people.

### Who it is for
- Retailers and chains who keep their store list in another system.
- Manufacturers and brands with dealer networks.
- Franchise systems, associations and care services with many sites.
- Teams that self-host n8n and want their location data to stay in Germany.

### Features
**Full location management.** Create, get, search, update and archive locations. "Get Many" filters by text, city, ZIP prefix, country, status, category or change date and can return all pages at once.

**Geocoding on create.** A new location needs only a name and a city. Without coordinates, My Store Locator finds the position from the address. You can choose the maps on which it appears.

**Maps, categories and statuses.** List maps with their embed token and number of locations. Category, status and map fields are dropdowns loaded from your account.

**Enquiries.** Read the enquiries visitors send through the contact form on your maps (Pro and Business), newest first.

**Polling trigger.** "My Store Locator Trigger" starts a workflow on new locations, changed locations or new enquiries. On activation it remembers the current state and then emits only new items.

**Webhook trigger in real time.** When you activate the workflow, the node registers its URL in My Store Locator and stores the signing secret. Every request is checked against `X-MSL-Signature` (HMAC-SHA256, at most 5 minutes old); invalid ones are rejected. Deactivating removes the webhook again.

**AI agent tool and no extra dependencies.** The action node can be used as a tool by n8n's AI agents. The package has no runtime dependencies besides n8n itself.

### Setup in n8n, step by step
1. Sign in to My Store Locator (Starter plan or higher) and open **API & Webhooks**.
2. Create an API key, name it "n8n" and choose the scopes: `locations:read`, `locations:write`, `maps:read`, `leads:read` (the webhook trigger also needs `webhooks:write` once it is live). Copy the key – it is shown only once.
3. In n8n open **Settings → Community Nodes → Install** and enter `n8n-nodes-mystorelocator`. Self-hosted with npm: `npm install n8n-nodes-mystorelocator` in `~/.n8n/nodes`.
4. Add a **My Store Locator** node to a workflow and create the credential **My Store Locator API**. Paste the key and keep the default base URL. n8n tests it with `GET /me`.
5. Choose resource and operation, for example **Location → Create**, and map the fields from the previous node.
6. For automatic starts add **My Store Locator Trigger** (polling) or **My Store Locator Webhook Trigger** (real time) and activate the workflow.

### Data protection and hosting in Germany
My Store Locator runs on servers in Germany. Owners and administrators confirm the data processing agreement (Art. 28 GDPR) in the app. The nodes send data only to the API you configure and do not track anything. API keys are stored hashed and can be revoked at any time; revoking also pauses their webhooks. With a self-hosted n8n your workflow data stays on your own server. Accounts can use two-factor authentication.

### FAQ
**Which plan do I need?**
Starter or higher for the API. Free accounts get `403 plan_limit`.

**Does it work on n8n Cloud?**
n8n Cloud shows only verified community nodes. Until verification, the nodes can be installed on self-hosted n8n.

**Polling or webhook trigger?**
The polling trigger needs no webhook and runs on n8n's schedule. The webhook trigger is instant and uses one webhook of your plan (Starter 10, Pro 25, Business unlimited).

**Do I need coordinates?**
No. Name and city are enough; street and postcode make the position more exact.

**Does Archive delete the location?**
No. It is archived and hidden from maps. You can restore it in the app.

**Which n8n versions are supported?**
n8n 1.x and 2.x (nodes API version 1).

**Is there a request limit?**
600 requests per minute per API key. Above that the API answers `429`.
